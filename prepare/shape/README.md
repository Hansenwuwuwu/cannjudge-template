# 测隐藏 case 的 shape

比赛通常只给算子数学定义，不给每个 case 的 `shape`。这个目录是一套通法：在**已经有一版全 Pass 基线**之后，用空转计时把每个 case 的维度测出来。

不绑定任何具体题目，换题只换档位表。

## 前提：先有一版 9/9 Pass 的基线

探针不能从零开始。原因：

- Judge 只对 Pass 的 case 给用时和误差，0/9 时用时栏是空的，什么都读不到
- 探针只加空转，不改数值，基线是安全网：某一轮如果变慢或挂掉，能立刻退回
- 空转长度是按基线用时留余量的，没有基线就不知道 1s 预算是多少

所以顺序是：先交基线 → 确认全 Pass → 在同一份代码上加探针 → 提交读用时 → 解码 → 再改探针 → 再提交。

## 第 0 步：确认 case 数量

Judge 返回的 `result` 数组长度就是 case 数。基线结果里直接能数出来，不用试探。

```powershell
python prepare/submit/auto_submit.py --read-only <baseline-id>
```

顶部会打印「通过 N/N」，这个 N 就是本次要测的 case 数。

## 第 1 步：决定测哪些量

一个 `shape` 可以拆成：

| 量 | 含义 |
| --- | --- |
| `rank` | 维度个数 |
| `d` | 最后一维 |
| `a`、`b`、… | 前导各维 |
| `M` | 前导维乘积，输出个数 = `M × d` |

建议顺序：

1. **先测 `d`**。算子性能通常由最后一维决定，它最能直接指导优化。
2. **再测 `rank`**。区分一维、二维、三维路径。
3. **再测前导维**。三维点先测 `a`、`b` 的量级，再收精确值。
4. **最后收尾**。把区间收成整数。

每一轮只测一个量。混在一轮里，读数会互相污染。

## 第 2 步：设计时间编码

把要测的整数映射到互不重叠的时间档位，让 Kernel 按真实值空转对应时间。

### 三种编码

**枚举表**，适合离散、取值少的量（比如 `d`）：

```
d=1 -> 30ms, d=4 -> 60ms, d=13 -> 90ms, ...
```

**线性**，适合取值范围小、需要精确值的量（比如 `M`）：

```
t = base + step × value
```

**区间/对数**，适合范围大、先看量级的量（比如前导维）：

```
index = round(t) - base
a_level = index / levels
b_level = index % levels
level 0 -> 1, 1 -> 2-3, 2 -> 4-7, ...
```

### 设计原则

| 原则 | 原因 |
| --- | --- |
| 档位间隔 ≥ 30ms | 小点抖动几微秒，Judge 只显示到 0.1ms，间隔太小分不开 |
| 单点附加 < 1s | 超过 1s 有被杀风险 |
| 全部 case 合计 < 3s | 之前一版合计 1.3s 以上直接 0/9，用时为空 |
| 必须有兜底档 | 区分「猜错了」和「空转没执行」 |
| 必须有正控制 | 至少放一个已知答案的档位，验证整条链路 |
| 已知值也要有空转 | 停在 0 的话，和「空转没执行」分不清 |

## 第 3 步：写探针

### Host 侧

只增加 tiling 字段，不改 shape 推导、dtype、输出：

```cpp
// 读真实维度
auto shape = input_x.GetStorageShape();
uint32_t rank = shape.GetDimNum();
uint32_t d = shape.GetDim(rank - 1);
uint32_t m = 1;
for (uint32_t i = 0; i + 1 < rank; ++i) {
    m *= shape.GetDim(i);
}

// 写进 tiling
tiling.rank = rank;
tiling.d = d;
tiling.m = m;
```

### Kernel 侧

```cpp
if (AscendC::GetBlockIdx() == 0) {
    uint32_t milliseconds = <按 tiling 字段选档位>;
    volatile uint32_t sink = 0;
    for (uint32_t i = 0; i < SPIN_PER_MS * milliseconds; ++i) {
        sink += i;
    }
}
```

`SPIN_PER_MS` 要标定：先空转固定 3ms，看 Judge 读数，按比例调。参考值约每 3ms 85240 次加法，换机器要重标。

### 三条硬约束

1. **只让 block 0 空转**。多块会乘时间，20 核的 case 会把 240ms 变成 4.8s。
2. **覆盖所有数值路径**。如果算子里有 `d==1`、`d==256` 这类特化分支，每一条都要有空转。漏一条，那个点停在微秒，看起来像「没执行」。
3. **不打印、不写日志、不改输出**。Host 只加 tiling 字段。

## 第 4 步：提交并解码

```powershell
# 提交探针
python prepare/submit/auto_submit.py --label probe-d

# 把九点用时贴给解码器
python prepare/shape/decode.py --spec prepare/shape/specs/table.example.json \
  --times "59.9 180 240 120 210 30.0 89.9 150 240"
```

`spec` 是你要测的量对应的编码定义，格式见 `specs/` 下的三个示例。

输出：

```
点 1  59.9ms -> 4
点 2  180ms -> 64
点 3  240ms -> 256
```

带 `--json` 可以输出数组，方便后续处理。

## 第 5 步：迭代收窄

典型四轮：

| 轮次 | 目标 | 编码 |
| --- | --- | --- |
| 1 | 最后一维 `d` | 枚举表，已确定的放正控制 |
| 2 | `rank` 和 `M` 或前导维 | 区间/线性 |
| 3 | 前导维的区间 | 对数编码 |
| 4 | 剩余维度的精确值 | 线性，基准 30ms |

每轮的读法：

- 整数毫秒直接读
- 带 `.9` 的是显示截断，按上一档算
- 微秒 = 空转没执行，先查路径覆盖
- 兜底档 = 猜错了，扩大候选范围
- 落在两个档位中间 = 档位设计有问题，或标定漂了

下一轮的已知值继续做正控制，不要删。

## 第 6 步：交叉验证

单靠计时可能出错，用三种旁证：

| 旁证 | 用法 |
| --- | --- |
| 误差百分比 | `0.78% ≈ 1/128`，能定元素总数 |
| 耗时比值 | 两个 case 的 `M` 比值应和某条路径的耗时比值一致 |
| 数值分支 | 改一条只在某个 `d` 才走的分支，看哪个点变了 |

`count_from_percent.py` 枚举和显示值相容的失败元素数：

```powershell
python prepare/shape/count_from_percent.py --percent 0.78 --max-n 1024
```

它只能给元素总数候选，不能单独定 `M` 和 `d`，必须和计时一起用。

## 第 7 步：记录

测完写一份 `shape_table.json` 放在本目录（文件由你新建），后续 `prepare/remote/config.json` 的 `cases` 直接用它：

```json
{
  "source": "第 N 轮探针，日期",
  "cases": [
    { "point": 1, "shape": [4], "rank": 1, "M": 1, "d": 4 },
    { "point": 2, "shape": [2, 64], "rank": 2, "M": 2, "d": 64 }
  ]
}
```

`shape` 写完整维度，`M` 写前导维乘积。

## 常见失败

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 0/9，用时为空，`FileNotFoundError` | 空转太长，任务被杀 | 缩短到单点 < 1s、合计 < 3s |
| 某点仍在微秒 | 那条数值路径没加空转 | 补上该分支 |
| 落在兜底档 | 候选值漏了 | 扩大枚举范围 |
| 读数比预期大很多 | 多块都在空转 | 检查 `GetBlockIdx() == 0` |
| 两轮读数矛盾 | 上一轮读错，或标定漂了 | 用正控制点复测 |
| 数值不再 9/9 | 探针动了计算 | 退回基线，只加空转 |

## 注意

- 探针版永远不要当最终提交，测完退回基线再优化
- 每轮只改一个量，改两个就无法归因
- 记录每轮的 spec 和读数，否则下一轮没有参照
- 题目公开 shape 时跳过整个目录
